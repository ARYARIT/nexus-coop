# NexusMC Coop Helper (Minecraft 1.12 – 26.x)

Мод внутри игры. Если лаунчер NexusMC не передал параметры `-Dnexus.coop=...`, он ничего не делает.
Когда мир загрузился, мод сам открывает его для сети на порту от лаунчера (только 127.0.0.1),
выключает проверку Mojang для этого мира и пишет `nexus-session.json` рядом с игрой.

## Как собрать (без установки Java)

В архиве восемь проектов: `./` (Fabric/Quilt, Minecraft с обфускацией), `fabric26/` (Fabric, Minecraft 26.x), `neoforge/`, `forge/` (Forge 1.16.5 – 1.21.8, на Mixin), `forge7/` (Forge 1.21.9 – 1.21.11, ForgeGradle 7), `forge14/` (Forge 1.14.4 и 1.15.2), `forge13/` (Forge 1.13.2) и `forge112/` (Forge 1.12.2). Последние три без Mixin, на событиях Forge. Workflow собирает всё сразу.

Какие версии собираются:

- **Fabric/Quilt:** 1.14.4, 1.15.2, 1.16.5, 1.17.1, 1.18.2, 1.19.2, 1.19.4, 1.20.1, 1.20.4, 1.20.6, 1.21.1, 1.21.4, 1.21.5, 1.21.8, 1.21.11; для 26.1.2, 26.2, 26.3 только Fabric (Quilt для 26.x нет)
- **NeoForge:** 1.20.4, 1.20.6, 1.21.1, 1.21.4, 1.21.5, 1.21.8, 1.21.11, 26.1, 26.2, 26.3
- **Forge 1.12.2** (файл для 1.12 – 1.12.2): проект `forge112/`
- **Forge 1.14.4, 1.15.2:** проект `forge14/`
- **Forge 1.13.2** (файл для 1.13 – 1.13.2): проект `forge13/`
- **Forge (экспериментально):** 1.16.5, 1.17.1, 1.18.2, 1.19.2, 1.19.4, 1.20.1, 1.20.4, 1.20.6, 1.21.1, 1.21.4, 1.21.5, 1.21.8, 1.21.11 (две последние самые неуверенные)

**Чего нет:** Fabric и Quilt для 1.13 (их там не существует) и Forge 1.13.0 – 1.13.1 отдельно не проверялись. NeoForge 1.20.1 использует файл Forge 1.20.1 (лаунчер подставляет его сам). Для версии без файла совместная игра просто не включается.

Каждый файл подходит для диапазона версий (в имени: `nexus-coop-fabric-1.20.2_1.20.4.jar` для 1.20.2, 1.20.3 и 1.20.4).

1. Залей **всё содержимое этой папки** в репозиторий GitHub с сохранением папок (`.github/workflows/build.yml` тоже).
2. **Actions** → `build-coop-helper` → **Run workflow** (именно новый запуск, не повтор старого). Подожди 15–30 минут.
3. Часть сборок может не собраться (красные в списке), остальные соберутся. Это нормально.
4. Внизу страницы запуска скачай архив **`nexus-coop-all`**: в нём готовые jar с правильными именами.
5. Положи все jar в `resources/coop/` проекта лаунчера. **Старые jar оттуда удали** (с именами вида `nexus-coop-fabric-1.21.jar`), иначе они будут мешать новым. Лаунчер сам выберет нужный файл по версии и загрузчику. Для версии без файла совместная игра просто не включается.

Если нужная версия красная, открой её лог и пришли мне последние строки с ошибкой. Ненужные версии можно убрать из `matrix` в `build.yml`.

## Для готовой версии лаунчера (.exe)

В настройках electron-builder добавь папку в extraResources:

    "extraResources": [{ "from": "resources/coop", "to": "coop" }]

## Как проверить

1. Запусти сборку Quilt или Fabric на 1.21.1.
2. В `latest.log` сборки найди строку `World opened for friends on 127.0.0.1:...`.
3. В Supabase в `game_sessions` у этой сессии `lan_ready` станет `true` без переключателя `nexusCoopDev`.
4. Выйди из мира в меню, `lan_ready` станет `false`. Зайди в мир снова, станет `true`.

## Как это работает в 1.12.2

У `shareToLAN` в 1.12.2 нет параметра «порт»: игра сама берёт случайный порт и слушает все интерфейсы.
Поэтому `forge112/` на время вызова подменяет `NetworkSystem` сервера на свой. Тот открывает сокет на порту лаунчера
и только на 127.0.0.1, а всё остальное делает сама игра (флаг «мир открыт», из-за которого игра не встаёт на паузу вместе с меню хозяина).
В `latest.log` ищи те же строки: `NexusCoop is active...` и `World opened for friends on 127.0.0.1:...`.
Тики берутся с клиента, а не с сервера: так мир откроется, даже если хозяин сразу нажал Esc.
У мода стоит `acceptableRemoteVersions = "*"`: друг без него (лаунчер не кладёт мод при входе в чужой мир) подключится без ошибки «mod missing».

## Как это работает в 1.14.4 и 1.15.2 (forge14)

Mixin в Forge этих версий нет, поэтому `publishServer` вызывается на сервере с подменённым `ServerConnectionListener`:
он открывает сокет на порту лаунчера и только на 127.0.0.1. Тики и остановка мира приходят из событий Forge.
Проект собирается ForgeGradle 3 на Gradle 4.10.3 и Java 8 с официальными именами Mojang.

## Forge 1.13.2 (forge13)

Тот же приём, что в `forge14/`, но подменяется `NetworkSystem` (в 1.13.2 нет официальных имён Mojang, код написан на именах MCP).
Если сборка падает на «cannot find symbol», поменяй `mappings_version` в `forge13/gradle.properties` на другой снимок MCP для 1.13.

## Старые версии (добавлено)

- `forge17/` (Forge 1.7.10) и Forge 1.8.9 собирается в `forge19/` (RetroFuturaGradle 1.8.9 не поддерживает).
- `forge19/` (Forge 1.8.9 - 1.11.2): ForgeGradle 2.1-2.2, четыре сборки в матрице.
- `legacyfabric/` (Legacy Fabric 1.8 - 1.12.2 (для 1.7.10 в Legacy Yarn второго поколения нет сборки)): Mixin на `MinecraftServer.tick`, метод открытия мира и сетевая часть находятся по сигнатуре.

Всё это собрано вслепую и требует прогона в CI и проверки в игре. Ornithe и Legacy Fabric 1.13.2 пока не сделаны.
